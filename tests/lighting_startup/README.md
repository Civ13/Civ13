`run.py --prepare-only` retains extracted production source, originals and exact-head receipts without launching BYOND. Runtime requires `--byond-bin <516.1681 bin>`; output defaults to fresh temporary storage. `--negative-control` inserts activity before the overlay barrier and must record early activations. Compile errors, runtime errors, engine background switches, open ports and timeouts fail independently.

The 40x32x4 native fixture (two bulk startup levels, one dynamic excluded level, and one initially dark level for fresh standalone constructors) compares immutable `0e9b527ec` with current startup and actual corner/overlay constructor bodies. Ordered shared masters, native corner ownership identity, activity, strict bulk overlay construction order, repeated initialization, default runtime corner callbacks and standalone creation entry points are checked. Fixture discovery uses a 64-candidate ceiling to force budget returns at modest geometry; production retains 4096 and 20% tick usage. Pool allocation/rendering, map fields and hook dispatch are isolated adapters. This is startup ordering evidence, not full-game lighting colors or performance evidence. Safe-mode loop protection remains enabled. Per-child compilation/runtime limits are 120 seconds. No native run has yet been performed locally.

Production startup owns only newly created corners in a temporary list, clears consumed references, creates all overlays before activity and publishes completion flags after activation. Ordinary constructors retain deferred callbacks. There are no external calls to the creation entry points in the current source inventory. Yielding exposes partially initialized data to other callbacks; completion consumers must continue honoring the existing flags. The full Beta constructor benchmark measures the actual large-map startup independently.

The fixture also extracts the real turf New and build-overlay bodies. Initial map construction schedules zero candidate overlay sleepers; a separate candidate-only scenario creates one native late replacement behind the overlay iterator, which must wait, then receive its overlay. Equal-workload snapshots and order lists are frozen before this scenario; its native identity, final 5120-row snapshot, direct activity waiter and two target overlay constructions are checked separately. Corner preservation uses the same saved-corners assignment as production ChangeTurf; other ChangeTurf behavior is outside this fixture. Every eligible startup turf must finish with four corners and exactly one overlay, rather than merely checking already-existing corners. A deliberately caught startup exception checks that the scalar barrier and completion flags clear and a waiting request returns. No engine errors are accepted as this cancellation witness.

The production scalar is transient. Only actual turf replacements/direct requests during startup wait; initial map New delegates to bulk construction. Runtime corner callbacks also wait on the scalar and abandon activity after a failed initialization. No new persistent request registry or one-waiter-per-map-tile fanout is introduced. The direct build-overlay callers are turf New, ChangeTurf and change_area.

A bounded compatibility pass over all world z-levels preserves the old initial turf callbacks' default overlay construction on dynamic areas skipped by the bulk sweep, including excluded levels and void indestructible turfs. It runs after bulk overlays and before corner activation. This adds one bounded world scan; performance requires the full-map benchmark. The fixture compares those historically skipped sites explicitly rather than silently changing their final overlay behavior.

Direct corner activity (including the real clear-overlay body) also waits on the barrier; only the startup owner bypasses it after overlay construction. The caught-error fixture exercises both a build waiter and a clear/activity waiter. Ordinary standalone corner callbacks and direct build calls while no startup is active retain historical behavior, tested with completion flags false after the error case. Native deletion is an isolated adapter for the clear test; production garbage-queue draining is not covered.

Exact `4ccb1cf42` cloud baseline and candidate both compiled with zero errors/warnings and returned without runtime errors; all four 5120-row state snapshots matched. The final mixed order comparison exposed an invalid shared race workload and a deliberate scheduling difference: at index 2558 baseline began its excluded-z3 delayed callbacks (`40,32,3`, `39,32,3`), while candidate built the late replacement and void fallback before traversing z3 forwards. Historical per-turf asynchronous callback order is not a portable synchronous-order contract. The fixture now requires strict equality of unchanged-geometry bulk constructor order, matching default-constructor eligibility/multiplicity, exact candidate compatibility order from an independently recorded native world traversal, and identical final shared-corner/overlay state including update-list registration and default rendering call count. Full mixed event order remains retained with an explicit scope label. Compiler-free controls must reject reversed bulk order, altered compatibility traversal, omitted fallback constructors and changed update registration; the native early-activation control remains independent. Existing lighting queue and full-source pool parity remain separate required evidence. The revised fixture awaits exact-head native compilation/runtime; preparation is not acceptance.

`--bulk-order-control` is a separate native control (mutually exclusive with `--negative-control`). It reverses the actual extracted production bulk overlay iterator in the generated candidate, preserving corner discovery and all original constructors. Both baseline and candidate must compile cleanly, return without engine/runtime errors, and retain identical final state and constructor eligibility; the strict bulk-order invariant must be the specific failure detected. The original mixed event stream is retained. This control does not modify repository production source.

Source consumer review: default overlay construction updates its own turf luminosity/color and registers the overlay for daylight visibility updates; `get_window_coeff()` can assign the shared corners' `window_coeff` in area-dependent constructor order. Current source uses that corner field only in a commented formula, while rendering uses the turf's own coefficient, so this shared assignment currently has no rendering consumer. No RNG or delayed callbacks occur in that calculation. The bounded compatibility pass intentionally changes partial startup and later update-list visibility scheduling; final eligibility, rendering inputs and membership are the parity contract. The isolated renderer stub records default update calls but does not establish real colors; full-source lighting queue/pool regressions cover those separately.
