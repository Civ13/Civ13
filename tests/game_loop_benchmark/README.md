# Native game-loop benchmark

Run from the selected Civ13 checkout on Windows:

```powershell
& '<verified-python.exe>' tests/game_loop_benchmark/run.py --byond-bin '<BYOND-516.1681-bin>' --output '<empty-evidence-directory>' --pairs 3
```

The runner alternates baseline/current fresh native DreamDaemon runs, with 1-3 pairs. Pair order reverses on the second pair to reduce order bias. Development can select one variant with `--variant current` or `--variant baseline`; default comparison always includes both. The baseline substitutes exactly `garbage.dm`, `__processScheduler.dm` and `_process.dm` from `7cfa850bd9d2788dcbb9fd35f5c5915ccb528dd2`; all other sources come from the selected checkout. It builds generated files without editing production. A shared generated macro counts evaluations and early returns of the real `PROCESS_TICK_CHECK` condition without changing the budget or branch. Source hashes, substituted sources, generated DME, probe, runner, compiled resources, logs, tracked public configuration, commit and dirty-state records are retained in evidence.

Normal Nomads startup remains active. Nine bounded cells become plating for eight separately placed humans. Their instrumented subtype counts calls and inherits production `Life()`. Its sole client-presence adapter returns FALSE from `ssd_check()` because ordinary disconnected humans are deliberately put to sleep by production status updates; client rendering, actual input and disconnection behavior remain untested. Per-actor natural/restart service counts and maximum inter-Life gaps are retained and require every actor to be serviced in both phases. Current-variant acceptance additionally requires maximum inter-Life gaps of at most 1.5 seconds during natural operation and 2 seconds after restart; calls must also stay within elapsed phase duration divided by the configured mob interval, rounded up with one boundary allowance. Observations are saved before these acceptance checks. Historical comparisons retain observed gaps, including the pre-existing exhausted-snapshot defect. The first human exercises production hand pickup/drop and native step movement 20 times, checking exact item/hand/turf identities. The callproc process executes 20 scheduled callbacks, measuring overdue time in deciseconds. Four hundred real effect constructions and qdel calls are recorded by weak reference plus native gcDestroyed timestamp. Reference IDs can be legitimately reused; unique reference counts are recorded separately. No matching retired identity may survive, and the actual collector queued-drain count must increase. The native probe observes 650 `sleep(1)` cadences. Actual elapsed duration depends on tick rounding, and is recorded in world deciseconds and awake intervals. At sample 601 it performs two immediate scheduler stop/start cycles; those last 50 cadences are tagged separately as a restart exercise.

Windows OS samples are taken approximately every 0.25 seconds. CPU is cumulative process kernel plus user seconds; private memory and working set are bytes. The poller tags startup, natural workload and restart phases by observing native ready/restart files. File visibility introduces up to one poll interval of boundary uncertainty, plus unquantified write/scheduling delay. Awake gaps are elapsed scheduling intervals, not CPU time or a direct duration measurement of every production tick. Natural versus restart performance must be reported separately, excluding startup from workload comparisons. Run final comparisons sequentially with other benchmarks stopped; development runs under concurrent host load are behavior validation only.

Game ports are closed at world startup, later reopening is rejected, native saved state stays in the evidence directory, and game webhook/ToRban adapters are disabled. BYOND itself can briefly announce an engine startup port and perform its account/hub login before the DM isolation hook; this harness does not establish OS-level network isolation. It does not restart production, attach a client, test client input/rendering, provide human gameplay acceptance, or establish a long-term memory/OOM result. Native runtime diagnostics, missing callbacks, failed identities, unserviced humans or undrained test effects invalidate a run. Healthy-phase tick-check evaluation coverage does not guarantee budget-triggered early exits; inspect the explicit early-return count and use the separate scheduler benchmark for controlled budget pressure.

Historical substitutions retain the current configured_interval_seconds helper required by shared object-process sources. The exact helper is saved with the generated historical process source and recorded in metadata; it does not replace historical scheduler or collector behavior.
