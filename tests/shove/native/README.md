# Native shove probe

Run only with explicit permission for an isolated trusted BYOND fixture:

```powershell
python tests/shove/native/run.py --output <fresh-directory> --byond-bin <516.1688-bin>
```

`--compile-only` does not start DreamDaemon. The runner stages the exact committed
HEAD using the existing full-source human fixture. Commit the probe and candidate
first. It neutralizes normal world/global startup through the existing reviewed
seams, denies clients and Topic, disables webhook configuration, closes the native
port at entry, and writes only to its new evidence directory. No production save
is imported or written and no live server is touched.

Windows retains the byte-identical current-engine owned-Job helpers and zero-socket
policy. A sampled startup listener can abort this fixture before world entry. Do
not retry with a weaker policy or claim that a clean compile is a passed runtime.
The manifest, compile logs, supervisor receipt and failed evidence are retained.

The 46 expected assertions cover the actual helper and native pulse path: cardinal
motion at three signed offsets, pulse count/completion/ownership, stamina and
recovery, wall and Help-intent body blocking, anchoring, disabled smooth movement,
exhaustion, range, grip release without displacement, chain immunity and size.
They are expectations until an accepted receipt confirms completion. Existing
fixture subtype counters observe actual Move and completion hooks; there is no
replacement shove implementation. This is headless evidence, not real-client
camera/rendering, multiplayer latency, full martial-art compatibility, every
map grace policy or live-server acceptance.
