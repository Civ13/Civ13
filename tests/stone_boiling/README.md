# Hot-stone source checks

`test_source.py` checks the production guard and callback wiring, and projects two timed interleavings: a complete admitted save during the wait and an empty/identical refill. Each projection includes separate hook-omission and comparison-omission controls which reproduce a false completion. The separate `tests/save_movement` source adapter executes the production persistence-admission and finish bodies with injected engine boundaries and checks accepted, refused and completed operations. These are offline source projections, not native DM execution or a real save round trip.

During development the first save-movement run failed with 29 errors and one failure in 58 tests: its source projection did not understand a newly inserted `new /datum` in the admission body. The implementation now creates a fresh identity in the operation constructor and the admitted operation publishes that identity; the fixture supplies a fresh constructor identity and projects the assignment. A subsequent initial 59-test run failed once because the projection did not declare the new global; the adapter now declares it. An accidentally displaced tail of the existing warning test was also restored before the final rerun. No persistence assertions were removed. The resulting suite passes 59 tests; hot-stone checks pass seven. Complete native/save and connected-client evidence remains outstanding.
