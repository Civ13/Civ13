# Offline tablet-press contract checks

Run with a verified interpreter, for example:

```powershell
py -3 -B tests/tablet_press/test_contract.py
```

The stdlib-only projection executes production year/research/construction guards,
transaction ownership/readiness, apply/balance/rollback, and raw metadata
copy/equality procedures. An injected constructor/holder adapter supplies
`prepare()`; static checks cover its exact acceptance receipts, output type,
capacity, metadata and unsupported-input admission. This is not a DM compiler
or a native reagent-holder, UI, callback, serializer or gameplay test.

Cases cover exact one-carbonate/four-aspirin payment and five-unit output,
unrelated ethanol/chlorine/traces, same-object rollback, duplicate/stale action,
save epoch and movement/actor interruption, metadata falsy/nested values and
bounds, loading merges, strict 1843/1844 construction/use admission, research,
and production stack's actual 20-unit admission and 18-unit debit behavior. Eleven
in-memory source mutations exercise date, research, debit, credit, rollback,
partial acceptance, owner, epoch and raw metadata controls.

Normal CI registers the suite in `scripts/ci_baseline.py`; a policy test runs the real registered child through baseline execution on
isolated production inputs, then mutates the date boundary and requires failed
counts, a failed baseline receipt and rejection by the required aggregate. No CI check is suppressed.

The existing aspirin reaction and all existing pill makers are unchanged.
Aspirin is not added to the controlled bench: source has no aspirin-specific
date/research policy. Main must select that availability policy separately.
The press's after 1843 floor is an equipment rule, not an aspirin invention date.

Native compilation, real holders/callbacks, normal menu clicks, ingestion and
save round trips remain unrun. Unexpected native faults are failures, not
conservation evidence.
