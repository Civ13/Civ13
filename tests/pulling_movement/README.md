# Pull-pair ownership foundation

The bounded ownership/capability kernel now has a default-OFF experimental
straight-leaf producer; see [PRODUCER.md](PRODUCER.md). Client input and an exact
native seam call it only after explicit opt-in. The existing
`human_subtile_unlinked` pulling guards remain byte-identical. This is not yet
approved for normal gameplay or default activation.

The first profile reserves a real-input human and an aligned, empty leaf item or
empty closet directly behind a straight cardinal intent. It rechecks reciprocal
pull pointers, real client/body/moving permission, actor state, shape, deadline,
independent movement ownership and target size/mobility. Vehicles, mounted guns,
football, living targets, loaded containers, chains, turns and diagonals are held.
The live-only coordinator holds at most 64 pairs/128 participant keys; neither
participant receives a new serialized field. Lease/capability/coordinator datums
are explicitly unsaveable. One registry must be used by the eventual producer.

Each participant capability binds its pair, member, ordinal, before/after physical
position, destination and direction. The follower cannot receive a token before
the leader's actual receipt matches its planned position. Reuse, foreign actors,
changed relation/client/position and late/early pulses refuse. Cancellation revokes
the issued capability. Release removes only matching ownership entries and refuses
to abandon a live offset. There is no timer/worker, movement, RNG, material/cost,
pathfinding, rollback, hook or browser action in this kernel.

The source-derived shift projection is checked against an independent world-pixel
oracle for 8,192 offset/direction/distance combinations. A separate straight-pair
oracle checks all 16 physical steps in four directions and the 2px transient gap.
Other tests are source/admission/phase contracts. They do not execute DM methods,
prove native collision, establish real-client authority behavior or approve the
feature for gameplay. No new native world or client has been launched.

Next implementation gates, in order:

1. Review/compile this kernel and prepare bounded positive/negative native lease
   scenarios with explicitly labeled fixture authority; retain the production
   real-client predicate. Runtime tests require separate reviewed scope.
2. Review the new producer's preserved slowdown/cooldown/cost/hook boundary and
   authenticated native seam before enabling its experimental profile.
3. Native-test the straight reverse resolver and the source lifecycle follow-up:
   deletion removes the retiring actor's keys/references, logout/handoff revokes
   the old controller, and callbacks unwind before completion/release. Partial
   orphans retain exclusive ownership and an explicit save hold. Automatic orphan,
   foreign transport, death/expiry/map-reset recovery remain default-enable gates.
4. Validate global save admission plus the direct participant checkpoint guard.
   Both require valid aligned live survivors and no active native/intent/completion
   work. Partial pairs/orphans hold saves before backend preparation; no half-pair
   capsule or runtime lease replays after load. Arbitrary-time partial saves remain
   unsupported rather than silently exporting one participant.
5. Test actual straight dragging before default enablement. Expand to living
   targets and turning only with reviewed native collision/authority contracts.
   Straight-line interpolation of both bodies during a 90-degree turn can overlap
   their 32x32 footprints, despite legal tile endpoints; do not hide this by
   disabling mutual/world collisions or falling through to raw placement.
