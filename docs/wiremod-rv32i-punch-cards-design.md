# Wiremod RV32I punch-card computer

**Status:** Proposed design for review. No runtime changes. The custom instruction set and private RAM in [prototype #2](https://github.com/Terra1/Civ13/pull/2) are not dependencies; its bounded execution and packed paging are useful references.

## Player flow

1. Write RV32I assembly on ordinary paper and feed it to the Punch Assembler. **Punch** either produces a numbered, ordered deck or returns line-numbered diagnostics without consuming the source or producing partial cards.
2. Insert the deck into a Punch Card Reader. Wire its `Data out` and `Word read` to the CPU's `Data in` and load strobe, and wire the CPU's `Ready` back to the reader. Wire the CPU bus to a separate RAM component.
3. Select Load, then trigger the reader. Wire the reader's Finished pulse to the CPU's Load complete input. Once the CPU confirms the image is loaded, switch to Run. Use Reset to restart at address zero with the loaded program intact. Disable the shell to wipe RAM.

## Assembler and media

- Use a bounded, two-pass assembler for [RV32I v2.1](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html): integer-register mnemonics, signed or unsigned immediates according to the encoding, and local labels. Specify syntax and any pseudoinstructions explicitly. Reject undefined or duplicate labels, invalid operands, out-of-range targets, and instructions outside the supported set. No includes, host commands, file paths, macros, or subprocesses. An external assembler is an offline test oracle only.
- A word is 32 bits. Each card is **10 × 80 = 800 bits = 100 bytes = 25 words**. Store format version and valid word count as card metadata, outside the 800-bit payload. Pack bits most-significant first within each word, left to right, then top to bottom; words may cross physical row boundaries. Keep counts and order when chaining existing decks. Never emit padding as instructions.
- `Trigger` starts reading from the front when idle. `Restart` cancels the current read and starts from the last card, preserving word order within each card. Reverse mode is a reader operation, not a way to run a forward-linked program. `Eject` cancels and returns cards in insertion order. Reject deck edits while reading; reset pending callbacks on eject, restart, removal, and shell disable.
- Publish each 32-character `Data out` before pulsing `Word read`. Do not advance while `Ready` is low. The CPU holds Ready low during the pending RAM write. Emit `Finished` once, after the last word is accepted; empty reads complete with no word pulses. A loader Fault signal aborts the reader and displays the error; it does not look like a successful Finished pulse.

## CPU and memory bus

- Load mode accepts exactly 32 ASCII binary digits, one word per strobe, and writes them to successive byte addresses starting at zero. Replacing an image invalidates the old executable range; Load complete commits the accepted nonempty range only when no RAM write is outstanding. A manual sender must issue its own Load complete pulse. Otherwise, a failed or interrupted load must not run as a partial image. Run fetches by program counter from external RAM, not straight from the card stream. This is necessary for backward branches and calls. Reject malformed words on input and trap invalid instruction encodings when fetched; keep the fault visible until Reset. Never represent arbitrary 32-bit words as BYOND floats: use binary text at pins and exact byte or limb storage internally.
- `Clock` is 1–500,000 requested Hz. Use a shared scheduler with fair per-shell and global work budgets for CPU work, bus events, and output signals. Do not queue debt while idle or waiting. `Triggered` pulses once per completed emulated clock cycle when connected; count that delivery against the same budget. Expose measured effective rate; 500 kHz is not a server throughput guarantee. Reset cancels pending requests, clears registers and fault state, sets PC to zero, and turns the CPU on. If no valid image exists, it waits for one.
- CPU outputs: `Address` as 32 binary digits, `Command` as 0 read or 1 write, `Data` as 32 binary digits, and `Chip select` as 0–255. Add a request strobe and an access-width pin (1, 2, or 4 bytes); add a reply plus acknowledgment/fault input path. Only one request may be outstanding; wait without busy looping. Match replies to the current request and discard late replies after reset. Use little-endian byte order in RAM; CPU does sign/zero extension.
- RAM inputs: `Address`, write-only `Data`, `Mode` (0/1), `Trigger`, and the access-width pin. Strings consisting solely of 0 and 1 are binary verbatim; permit explicit decimal for manual wiring (for example, `0d10`), with overflow rejected. CPU traffic always uses fixed-width binary text. Read `Output` returns a zero-padded binary word; writes consume only the addressed bytes. Acknowledgment must not depend on whether output data changed. A store is all-or-nothing; reject unmapped or misaligned accesses in this execution environment.
- Allocate a shared 512 KiB byte-addressed window (`0x00000000–0x0007ffff`). Reserve 1,024 bytes per small RAM chip first, then divide the remaining whole words as evenly as possible among standard chips in stable mounting order. A blocked or ambiguous topology faults; use an address decoder for multiple chips so only the addressed bank replies. Lock topology while enabled; changes require disable/re-enable and a RAM wipe. RAM is volatile on every disable path; do not serialize contents or restore CPU work on load. Lazy pages must also honor a separate world-wide host-memory budget.
- An `SB` to `0x00080000` emits the low byte on `Chip select` without accessing RAM, even when consecutive bytes match. Treat other accesses to that address as unmapped. Define deterministic handling of reserved encodings, `ECALL`, and `EBREAK`; no host services. With ordered, single-outstanding bus transactions, `FENCE` may retire after prior memory operations are acknowledged. No optional ISA extensions are implied.

## Delivery and acceptance

1. **Assembler and reader:** Compare exact emitted words with a reference RV32I assembler. Cover 1, 25 and 26 words, partial final card, chained ordering, reverse card order, backpressure, and restart/eject during a read. Invalid input must produce no cards. As a packing check, `addi x1, x0, 1` encodes as `0x00100093`, or `00000000000100000000000010010011` on the wire (bytes `93 00 10 00` in RAM).
2. **Wireable RAM:** Check splits, 1 KiB reservations, endianness, partial writes, last byte, unmapped access, isolation across shells, and wipe on all disable paths. Test that a rejected write leaves every byte intact.
3. **CPU integration:** Load a two-card program that branches backward, reads back a stored byte, and sends 65 to Chip select. Compare instruction and register results against an independent implementation. Cover reset during a pending reply, arithmetic wraparound, bad instructions, memory stalls, and repeated identical output values. Measure effective throughput and server tick cost with many busy shells and feedback wiring before picking production budgets. Use isolated fixtures only.

Review decisions: confirm the added load/run control and bus handshake, reverse-card behavior, strict alignment, and the one-byte chip-select register before locking the component pins.
