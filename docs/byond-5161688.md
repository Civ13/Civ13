# BYOND 516.1688 source upgrade and acceptance

The source launcher 1.0.8 and default hosted compiler target **516.1688** through
`tools/byond/version.json`. WSL setup uses the same reviewed target. The manifest
retains compiler minimum 516.1681 and savefile major 516; this patch uses no new
game API and makes no save-format or asset change. Ordinary client admission still
has the historical major-version floors; that is not mixed-version acceptance.

The [official download page](https://www.byond.com/download/) identifies 516.1688
as stable. Its [release notes](https://www.byond.com/docs/notes/516.html) describe
server reference/external-call fixes, compiler macro handling and a WebView2
cursor fix. The manifest's Linux ZIP and Windows installer sizes/hashes were
observed on official HTTPS downloads on 2026-10-24. They pin exact bytes, not a
BYOND-published checksum or independent authenticity. The downloader accepts only
the exact versioned official URL or explicitly selected reviewed Linux community
mirror URL, refuses redirects/existing outputs, bounds bytes/time, and checks
the unchanged official-observed size/hash before publishing for extraction.

The active hosted build explicitly selects the unofficial
[BYOND Build Mirror](https://byond-builds.dm-lang.org/516/) used by
[tgstation's installer](https://github.com/tgstation/tgstation/blob/898eaa5c6947b3920c6ee2f59fd89532ae1b7fae/tools/ci/install_byond.sh).
Its exact `516/516.1688_byond_linux.zip` returned 4,887,281 bytes with SHA-256
`16278f318cdeb4b77c57868dd7135032fde717ea6226269d22b2a1a50968e7f9`
on 2026-10-24, matching the prior official observation. This does not turn the
mirror into an official source. No headers, proxies, certificate exceptions,
automatic source fallback or repeat attempt against the blocked official route
is added. The default standalone downloader/Windows/WSL source remains official;
the hosted job passes its explicit community source choice to the bootstrap.

Hosted cache keys contain the OS (`linux`), exact version and expected archive
hash. Only the archive plus its acquisition receipt are cached, never an installed
BYOND tree. Cache hits validate receipt scope/origin and recheck every archive
byte before fresh extraction, setup and actual compilation. Corrupt or incomplete
cache entries fail with evidence retained; they are not overwritten or retried
through another host. There are no prefix restore keys. Cache-origin metadata is
an audit record, not independently authenticated proof of download history.
Successful compiler and aggregate receipts require exact version/hash/size,
official/community/cache source and upstream URL provenance, as well as the
executed compiler version and zero-error/zero-warning log. Cache hits cannot
substitute for compilation. Cache save occurs only after successful compilation.

Windows requires Windows 10/11, 32-bit WebView2 and Visual C++ runtimes. Passive
installer metadata reported 5.0.516.1688. The Linux archive is 32-bit x86 and
references GLIBC_2.34 symbols. Static inspection does not establish that either
platform can load/run the target. Linux has compiler/server support, no playable
DreamSeeker client.

`tests/test_byond_toolchain.py` checks pin validation, exact source URLs,
injected cold/warm/corrupt caches and archive failures, source receipts, exact
compiler logs and source embedding/version coherence. It performs no network or native
execution. The expanded C# tests cover actual requirement parsing/PE matching,
local-daemon compatibility messages and existing updater/installer adapters;
new hosted results must identify the exact tested head. The launcher workflow
also runs the existing purely mocked SocialContracts suite with isolated SDK
state, a four-minute bound and retained assertion/log/source receipts. No local
.NET execution or actual Discord/BYOND operation is authorized by these changes.

## Acceptance gates

| Coverage | Status before hosted review |
|---|---|
| Official download metadata/hash/static package inspection | Observed, retained for reproducibility |
| Inspected Python/Bash source contracts | Run separately with exact patch/tree and counts; not native evidence |
| Linux DreamMaker 1688 full game | Pending exact-head hosted build with complete source/assets, exact banner, 0 errors/warnings and required CI receipts |
| Windows compiler | Not run; separate platform claim needs its own admitted check |
| Linux/Windows DreamDaemon 1688 | Not run; startup, extensions, GC/collections and lifecycle require isolated native checks |
| Save/load | Not run; isolated 1681-to-1688 import and 1688 round trips must preserve aliases/alists/cycles, inventories and lighting, reject malformed input before mutation and retain originals |
| Launcher build/update/setup | .NET/EXE tests not run locally. Hosted exact-head build/mock updater checks do not prove actual BYOND installer, WebView2 prerequisites or game behavior |
| DreamSeeker 1688 -> server 1688 | Not run; real isolated join/spawn, input/UI/Topic, cursor/focus, nested-eye/rendering, lighting/resources/audio and disconnect acceptance remain separate |
| Mixed 1681/1688 pairs | Unknown; do not infer support from the old major-version floor |
| Production and release/feed | No deployment, restart, installer launch or publication performed |

Keep the current local execution/process-inventory holds. Do not dispatch held
probes, modify saves or run the deployment/WSL scripts from source approval alone.
Main reviews the complete patch before push and owns readiness/merge/post-merge
verification. A future server toolchain replacement needs a coordinated daemon
restart. Launcher rollout needs a new exact-tag build/release and separately
authorized stable-feed advance. Keep previous binaries and original saved-world
generations; reverse compatibility of newly written saves is unproven.

Future new-version detection/automatic PR/merge work is deferred until these
compatibility gates are resolved. The central manifest is data for that later
work, not an instruction to install, publish or trust external release text.
