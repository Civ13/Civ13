# Disabled paper editor entrypoint candidate

This local dependent slice builds on the accepted inactive editor and #3502.
`PAPER_EDITOR_ENTRYPOINT_ENABLED` is a compile-time constant set to `FALSE`.
The existing pen attack continues to open the legacy editor. No server or player
setting turns the new route on. The prospective route consumes a failed admission
rather than falling through to an unclassified legacy write. Unsupported legacy
HTML, crayon, renderer or transport cases use the complete projected read-only
classic preview already supplied by the editor; historical authored links retain
their existing classic behavior. This does not finish editing those papers.

After a canonical append commits, rebuild the item's legacy link cache and call
its existing icon override. A classified section counts as writing for the base
paper icon; the icon does not carry section text. Rejected edits do not refresh.
The cache remains derived from legacy `info`, not classified sections. Existing
subtype icon overrides and the original crumpled-sheet check remain in place.

Before enabling this route, finish and independently review full rich-legacy and
crayon editing compatibility and the legacy field/EOF transition; verify native
transport, owner/custody and event ordering, close/logout/body transfer, language
projection, save/reload and icon/link behavior using an admitted isolated client.
The serialized Python fixture is not BYOND savefile acceptance. Native testing,
activation and deployment are outside this local patch.
