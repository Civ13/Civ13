# Canonical physical paper mutations

This dependent source slice keeps the inactive lifecycle candidate immutable.
It adds no player editor, language selector, study action or activation switch.

Existing Rename paper labels the public item name/description; it does not replace
language-tagged written title sections. The candidate retains that distinction:
the legacy name mirror and canonical legacy snapshot change together, and section
text/languages/ink/signatures remain exact. This public-label policy must be
accepted explicitly in source review; it is not a hidden classified-title bypass
or a new confidentiality claim. The future editor must use language-bearing title
sections for written titles. No classified document is newly created by this slice.

Rename captures its existing canonical edit and physical snapshot before the
prompt. The response binds the original body/client and current one-level held
custody, rejects changed records/legacy data, and commits the synchronized name
before description/fingerprint effects. It retains the existing pen-free label
interaction and does not expand container admission. Arbitrary leave-and-return
excursions during this legacy prompt are not claimed detected; the future editor
must use the reviewed session lifecycle rather than forwarding this verb.

Fold uses the same internal name transaction before applying the existing airplane
icon, throw range and fingerprint. Malformed/stale/over-limit canonical state
refuses without those partial effects. Name prefixes, repeat folding, original
capacity and written sections otherwise retain existing semantics.

Crumple uses the existing stars(info,85) damage rule once per invocation for old HTML and once
per canonical section, then atomically commits. Reads and copies use those stored
results and never reroll. Inherited medieval-scroll re-crumpling is unchanged;
this is not a lifetime damage limit. Each changed text section advances its version while
preserving lineage, language, kind, ink and tool; unchanged text retains its
version. Document identity/section sequence/capacity/stamps are retained. Revision
or changed-section version exhaustion refuses the entire candidate before physical
content/icon/message effects. Unsupported records do not fall back to raw writes.

Offline tests execute complete helper and transaction/copy procedures with a
deterministic randomness seam, inert client/object/list boundaries and source
contracts around the old verbs. They are not native randomness/Unicode, prompt
delivery, recursive listener ordering or actual inventory acceptance. Existing
legacy/classified projection and copy tests remain selected by ordinary CI.
No new dependency or native runtime fixture is selected.

Minimal TGUI Paper integration points after source acceptance:
- Invoke the existing authoring begin, bind_ui, snapshot, append and cancel API;
  bind before opening on the current TGUI adapter. Never expose canonical/edit or
  copy snapshots, and never route arbitrary old hrefs into the action handler.
- Use only server-returned language choices/default; body/title/signature writes
  carry the current lease/document/revision and are revalidated server-side.
- Display projected known/unknown runs and ink on the equivalent opaque white
  page, with no hidden unknown originals. Legacy rich HTML requires a bounded
  faithful representation or the complete authorized classic reader fallback.
- Preserve the existing legacy field/EOF editor only for unclassified documents;
  classified authoring must not downgrade an unsupported request to that editor.
- Wire icon/link refresh after accepted writes using canonical content presence;
  current legacy icon heuristics inspect info alone and need this narrow adapter.
- Verify real client close/logout/transfer, pen/custody excursions, native event
  cleanup, mixed-language nonleakage and save/load under an admitted isolated
  executor before enabling the editor. Native execution/live deployment remain held.

Study, forms/templates, stamps and filing remain separate features.
