# Canonical paper facsimiles

This source slice builds on the merged transaction service. It does not enable
typed authoring, the TGUI editor, forms, study or automatic translation.

The printing press and faction mailbox now copy the server-owned canonical
document and its bounded physical legacy snapshot. Copies receive a fresh
document ID; section IDs, text lineage/version, language IDs, ink, signatures,
dates and legacy bytes remain unchanged. They do not inherit character study
progress or create government authority. Each output owns its record and physical
lists, rebuilds its own href cache and skips a second delayed capacity debit.
Stored stamp metadata is retained; this does not repair stamp display/authoring.

Legacy documents stay unclassified. The existing generic-paper output type for
legacy subtypes remains a facsimile, without subtype authority fields. Classified
subtypes refuse whole until their constructors and physical authority have a
reviewed adapter. Unknown schemas, invalid records, stale physical/canonical
snapshots and over-budget data refuse whole rather than dropping classified text.
The existing 1024-node legacy and 4096-node record budgets remain in effect.

Press insertion rechecks the actual controller, held paper, available slot and
snapshot around its prompt, then uses the existing held-item transfer into real
machine custody. Copying rechecks both inputs, session and custody after the
existing 90-tick do_after and after private output construction. Cancellation
retains inputs; rejected constructed output is deleted. Success returns the
original and copy and consumes only the stock. Destruction releases retained
papers at the machine's turf, including old nullspace input lists; books keep
their existing behavior. A press destroyed in nullspace has no invented recovery
turf. No asynchronous transaction is promised across arbitrary engine callbacks.

Mail prepares all selected receiving-box outputs before final source/session,
faction and receiver-location checks. Failure cleans owned unpublished outputs
and retains the original. Success publishes independent facsimiles and consumes
the original once. This is the existing faction fanout, not authenticated mail.

Teleprinters retain legacy output but refuse classified input and skip classified,
deleted or lost-custody stock at print time. They do not yet have a written-language
or scribe context; exclusion is a dependency boundary, not language-aware telegram
authoring. Classified rename/crumple/airplane and other remaining physical mutation
paths still need their own integration before player-facing authoring activates.

The new test file executes complete selected production procedures through the
existing strict stdlib adapter. Its seams explicitly replace allocation, client and
physical objects, clock/telegram formatting, inventory transfer, do_after, typed
world enumeration, icon/href effects, parent destruction and qdel. Unknown syntax
and call boundaries fail preparation. It covers mixed-language projection after
canonical copies, null/path preservation, detached ownership, stale/concurrent
snapshots, sessions, cancellation, construction callbacks, fanout cleanup and
legacy teleprinter controls. Local-only causal mutations require real assertion
failures, not parser errors. They are not native BYOND or real-client acceptance.

Native constructor/save-load timing, path/string distinctions in JSON stale
fingerprints, engine movement/deletion callbacks, sprites, Unicode indexing and
actual network/client delivery remain unverified. The existing paper runtime's
socket-isolation hold is unchanged. No Gaia state or save migration is involved.
